# MealMate 🍽️

MealMate is a mobile app (built with **Expo / React Native**) that helps friends discover nearby restaurants and plan meals together. It was built as a diploma project.

## Features

- **Authentication** – sign up / log in with email and password (Supabase Auth)
- **Restaurant map** – find nearby restaurants, cafés, bars and bakeries on a map, search for places, and see distance, rating, opening hours, phone number, photos and reviews (Google Maps Platform)
- **Meal plans** – create a meal plan for a restaurant, invite friends, accept/decline invitations and leave reviews
- **Group chat** – every meal plan gets a chat for its members
- **Notifications** – in-app notifications for invites and meal plan updates
- **Profile** – edit your profile and upload a profile picture (Supabase Storage)

## Tech stack

| Area | Technology |
| --- | --- |
| App framework | [Expo SDK 52](https://docs.expo.dev/), React Native 0.76, [Expo Router](https://docs.expo.dev/router/introduction/) (file-based routing) |
| Backend / database | [Supabase](https://supabase.com/) (Postgres, Auth) |

| Maps & places | [Google Maps Platform](https://developers.google.com/maps) via `react-native-maps` and `react-native-google-places-autocomplete` |


## 1. Prerequisites

- [Node.js](https://nodejs.org/) 18 or newer (LTS recommended) and npm
- [Git](https://git-scm.com/)
- A [Supabase](https://supabase.com/) account (free tier is fine)
- A [Google Cloud](https://console.cloud.google.com/) account with billing enabled (required for Maps APIs; there is a free monthly credit)
- To run on a device/emulator:
  - **Android:** [Android Studio](https://developer.android.com/studio) with an emulator, or a physical Android phone with USB debugging enabled
  - **iOS (macOS only):** Xcode with an iOS simulator

## 3. Set up Supabase

1. Create a new project at [supabase.com](https://supabase.com/dashboard).
2. Go to **Project Settings → API** and copy the **Project URL** and the **anon public** key.
3. Under **Authentication → Providers**, make sure **Email** is enabled.
4. Create the database tables the app uses (**Table Editor** or **SQL Editor**):

   | Table | Used for |
   | --- | --- |
   | `users` | User profile (name, image, ...) linked to the Supabase Auth user id |
   | `userLocation` | Last known location of each user |
   | `meal_plans` | Meal plans (restaurant, date/time, creator) |
   | `meal_plan_users` | Which users are in which meal plan |
   | `meal_plan_reviews` | Reviews written for a meal plan / restaurant |
   | `invitations` | Meal plan invitations between users |
   | `notifications` | In-app notifications |
   | `chats` | One chat per meal plan |
   | `group_members` | Members of each chat |
   | `messages` | Chat messages |

   > Check the `supabase.from('...')` calls in `app/` and `services/` for the exact columns each screen reads and writes.

5. Go to **Storage** and create a bucket named **`uploads`**, set it to **Public** (profile pictures are loaded from its public URL).
6. If you enable Row Level Security (recommended), add policies that let authenticated users read/write the rows they need.

## 4. Set up Google Maps Platform

1. In the [Google Cloud Console](https://console.cloud.google.com/), create (or select) a project.
2. Go to **APIs & Services → Library** and enable:
   - **Maps SDK for Android**
   - **Maps SDK for iOS** (if you run on iOS)
   - **Places API**
   - **Geocoding API**
   - **Distance Matrix API**
3. Go to **APIs & Services → Credentials → Create credentials → API key** and copy the key.
4. (Recommended) Restrict the key to the APIs above.

## 5. Add your keys (config files)

Secrets are **not** committed to GitHub (both files below are listed in `.gitignore`). Every person who clones the project has to create them.

**a) `constants/index.js`** – Supabase keys

```js
export const supabaseURL = "https://YOUR-PROJECT-ID.supabase.co";
export const supabaseAnonKey = "YOUR-SUPABASE-ANON-KEY";
```

**b) `.env`** in the project root – Google API key

```env
GOOGLE_API_KEY=YOUR-GOOGLE-API-KEY
EXPO_PUBLIC_GOOGLE_API_KEY=YOUR-GOOGLE-API-KEY
```

- `GOOGLE_API_KEY` is read in the app code (`import { GOOGLE_API_KEY } from "@env"`).
- `EXPO_PUBLIC_GOOGLE_API_KEY` is read by `app.config.js` to configure the native Google Maps SDK.

> After changing `.env`, restart Metro with a cleared cache: `npx expo start -c`

## 6. Run the app

This project uses native modules (`react-native-maps`, `expo-dev-client`), so the recommended way to run it is a **development build** rather than Expo Go.

**Android** (emulator running or phone connected):

```bash
npx expo run:android
```

**iOS** (macOS only):

```bash
npx expo run:ios
```

The first build takes a few minutes. After that, you only need to start the dev server:

```bash
npx expo start --dev-client
```

> **Map shows blank / grey on Android?** The `android/` folder may have been generated before the Google key was set. Regenerate it so the key from `.env` gets written into the Android manifest:
>
> ```bash
> npx expo prebuild --clean
> ```

### Building an APK / app with EAS (optional)

The project is set up for [EAS Build](https://docs.expo.dev/build/introduction/) (`eas.json`). Add your secrets as EAS environment variables, then:

```bash
npm install -g eas-cli
```

```bash
eas build --profile preview --platform android
```

```bash

```


Then open a **Pull Request** on GitHub to merge `my-feature` into `main`.

### ⚠️ Before you push: keep your keys secret

- Never commit `.env` or `constants/index.js` – they're in `.gitignore`. Run `git status` before committing and make sure they don't appear.
- If you accidentally committed a key, **rotate it** (create a new key in Supabase / Google Cloud and delete the old one). Removing the file in a later commit is not enough, because it stays in the git history.
